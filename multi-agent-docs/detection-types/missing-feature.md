# missing_feature 탐지 기준

## 정의

`missing_feature`는 최신 기준 문서에 명시된 기능, 사용자 흐름, 비즈니스 규칙, API 동작이 수집·분석된 코드 범위에서 구현 근거로 확인되지 않는 경우를 의미한다.

## 적용 조건

- `comparisonBasis`가 `document_latest` 또는 `unknown`일 때 사용한다.
- 문서가 기능 요구사항을 구체적으로 설명해야 한다.
- 분석 대상 코드에서 해당 기능을 구현하는 endpoint, function, class, UI 흐름, 설정, 테스트 등의 근거를 찾지 못해야 한다.

## 분석 절차

1. 문서에서 기능 요구사항을 추출한다.
2. 요구사항과 관련된 키워드, 도메인 용어, API path, 데이터 필드를 정리한다.
3. 분석 계획에서 지정한 코드 파일과 정적 코드 신호를 확인한다.
4. 동일하거나 동등한 구현 근거가 있는지 찾는다.
5. 구현 근거가 없으면 `수집·분석된 코드 범위에서 구현 근거를 확인하지 못했습니다`라고 표현한다.

## 필요한 근거

- 문서 근거: 요구사항이 드러나는 문장, heading, pageNumber 또는 matchedText.
- 코드 근거: 관련 파일을 찾았지만 구현이 없는 정황, 비어 있는 route/service, 유사 기능만 있는 코드, 또는 관련 파일 부재.
- 범위 근거: 수집된 파일 수, 분석된 코드 청크, GitHub tree truncation 여부.

## 제외 조건

- 문서가 아이디어나 향후 계획처럼 표현되어 필수 구현 요구사항인지 불명확한 경우.
- 코드가 다른 이름으로 동등 기능을 구현하고 있는 경우.
- 수집 범위가 부족해 관련 영역을 거의 보지 못한 경우.
- `code_latest` 모드인 경우.

## Severity 기준

`high`:

- 핵심 사용자 흐름, 인증/권한, 결제, 데이터 손실 방지, 주요 API처럼 제품 사용에 직접 영향을 주는 기능이 누락된 경우.
- 문서가 명확한 필수 요구사항으로 설명하고, 관련 코드 근거가 거의 없는 경우.

`medium`:

- 보조 기능, 운영 기능, 일부 사용자 그룹에 영향을 주는 기능이 누락된 경우.
- 대체 흐름은 있지만 문서 요구사항을 완전히 만족하지 못하는 경우.

`low`:

- 작은 편의 기능, UI 표시, 부가 메타데이터, 문서 표현과 구현 명칭 차이처럼 영향이 제한적인 경우.
- 근거는 있으나 일부 탐색 범위 제한이 남아 confidence가 낮은 경우.
