# outdated_doc 탐지 기준

## 정의

`outdated_doc`는 코드에는 구현되어 있지만 업로드 문서에 설명되어 있지 않거나, 문서가 더 오래된 동작을 설명하는 경우를 의미한다.

## 적용 조건

- `comparisonBasis`가 `code_latest` 또는 `unknown`일 때 사용한다.
- 코드 구현 근거가 구체적으로 확인되어야 한다.
- 문서에서 해당 기능, API, 동작, 설정, 데이터 필드에 대한 설명을 찾지 못하거나 오래된 설명만 확인되어야 한다.

## 분석 절차

1. 코드에서 endpoint, function, class, UI flow, config, schema 등 구현된 기능 신호를 확인한다.
2. 해당 구현이 사용자 또는 운영자에게 의미 있는 기능인지 판단한다.
3. 업로드 문서에서 같은 기능 또는 동등한 설명을 검색한다.
4. 문서에 없거나 오래된 형태로 설명되어 있으면 `outdated_doc` 후보로 분류한다.
5. 문서 최신화에 필요한 section, title, 핵심 설명을 추천한다.

## 필요한 근거

- 코드 근거: 구현 파일, symbolName, line range, endpoint method/path.
- 문서 근거: 관련 설명이 없다는 검색 범위, 오래된 설명 matchedText, 문서 heading.
- 추천 조치: 어느 문서 section에 어떤 설명을 추가하거나 수정해야 하는지.

## 제외 조건

- 내부 구현 세부사항이라 사용자 문서에 쓸 필요가 없는 경우.
- 실험용 dead code, 미사용 함수, 테스트 fixture, generated file인 경우.
- 문서가 다른 이름으로 동등 기능을 설명하는 경우.
- `document_latest` 모드인 경우 최종 finding으로 보고하지 않는다.

## Severity 기준

`high`:

- 코드에 새 핵심 기능이나 API가 구현되었지만 문서에 없어 사용자가 기능을 알 수 없거나 연동에 실패할 수 있는 경우.
- 운영, 보안, 데이터 처리 방식이 문서와 달라 잘못된 사용을 유발할 수 있는 경우.

`low`:

- 보조 기능, 신규 옵션, 일부 workflow가 문서에 빠져 사용성이나 운영 효율에 영향을 주는 경우.
- 문서가 예전 방식만 설명해 사용자 혼란 가능성이 있는 경우.
- 작은 편의 기능, 부가 field, 내부 옵션처럼 영향이 제한적인 경우.
- 문서 추가가 있으면 좋지만 즉시 장애나 큰 오해로 이어질 가능성이 낮은 경우.
